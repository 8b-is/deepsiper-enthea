# Agent Note: 认证代理按请求证明配置访问权限

Status: implemented

[English](2026-11-01-authenticated-proxy-settings.md) | 中文

## Problem

经过已认证公开反向代理的浏览器使用非回环主机名。按该主机名限制所有设置请求及偏好存储，会阻止合法配置；而把可信主机名当作认证，又会向未认证部署开放设置。

## Decision

[Connection](../../../../packages/client/connection/README.md) 接受明确的认证代理配置：一个规范 HTTPS Origin 和私有令牌文件。上游仅绑定回环。代理认证所有公开路由并替换内部证明请求头；Connection 在分发管理员操作前验证真实对端、权威、浏览器来源和密钥。证明在交给 RPC 消费者前移除。原生桌面操作仍仅限回环。

[浏览器信任决策](2026-07-28-api-browser-trust-boundary.md) 保持有效：Host/Origin 和媒体类型检查独立于认证保护所有请求。本记录提供单独的代理认证机制，不把 `trustedHosts` 扩展为授权名单。

浏览器通过不可缓存的 Connection 端点读取按请求确定的权限。权限属于连接 generation，不属于静态启动标记。设置存储等待授权，获准后读取权威主机值，撤权后丢弃过期响应。内存偏好不会静默迁移到持久配置。

## Alternatives considered

**授权所有 `trustedHosts` 条目。** 拒绝，因为该名单用于 DNS rebinding 防御，也包含未经认证的部署。

**把公开 Host 和 Origin 改写为 localhost。** 拒绝，因为它破坏浏览器来源证据，并错误授予桌面访问权限。

**不检查密钥或回环对端，只信任代理请求头。** 拒绝，因为外部请求头可伪造管理员权限。

**在 Connection 内增加用户登录和账户。** 暂缓，因为现有代理拥有认证职责；此能力授予可信管理员连接，不提供多用户隔离。

## Consequences

代理必须认证整个应用、替换内部请求头、保留浏览器来源并保护令牌。轮换需协调重载，不一致期间拒绝访问。凭据和模型发现均为管理员能力，包括主机侧端点探测。Host 测试验证拒绝路径和共享拦截器前的授权；浏览器生命周期测试覆盖授权、撤权及迟到响应。此机制不识别个人用户，也不为工具提供沙箱。
